\section{Introduction}\label{sec:intro}

Nearest-neighbor search asks a simple but fundamental question: given an object, which objects in a reference collection are most similar to it? In modern data systems, these objects are often represented as high-dimensional feature vectors, and similarity is measured by a distance function over those vectors. The $k$-nearest neighbor (kNN) search returns the $k$ closest reference objects for one query object. A kNN join lifts this operation from one query to a whole query set: for every object in a query set $U$, it maintains the $k$ closest objects in a reference set $I$. The result is a materialized neighborhood table between two sets, rather than a collection of isolated nearest-neighbor queries~\cite{bohm2003supporting,bohm2004k,xia2004gorder,yu2007efficient}.

This paper studies a stronger dynamic version of this problem, which we call dual-dynamic kNN join. In this setting, both sides of the join evolve: new query objects may arrive, old query objects may be removed, new reference objects may be inserted, and existing reference objects may disappear or be retired. The goal is to keep the kNN join table current after each update without recomputing the entire join from scratch.

Dual-dynamic kNN join is useful whenever two evolving collections of high-dimensional entities must be compared continuously. In healthcare, a patient can be represented by a vector built from diagnoses, laboratory tests, medication history, imaging features, and temporal clinical indicators. New patients are admitted, existing records are corrected, and reference cohorts change as medical databases are updated. Maintaining patient-neighborhood relations can support case reanalysis, similarity-based risk prediction, and diagnosis assistance, where unstable or incorrect neighbor relations may affect downstream clinical decisions~\cite{an2023comprehensive,fang2021patient,gottlieb2013method}. In finance, transactions, accounts, or market states can be encoded by high-dimensional behavioral and temporal features. Fraud analysts and monitoring systems need to track which new activities are close to suspicious historical patterns while the historical reference set itself changes as new confirmed fraud cases, legitimate cases, and market observations are added~\cite{al2021financial,immadisetty2025real,li2023artificial,gao2024machine}. Similar needs also arise in recommendation, anomaly detection, security monitoring, scientific data analysis, and vector-database workloads, where embedding-based objects and their reference collections are continuously refreshed~\cite{ahuja2019movie,tian2014anomaly,li2007network,wang2020log,pan2024survey}.

The problem is difficult for three reasons. First, contemporary data volumes and feature dimensions keep increasing. Rich representations encode many attributes of an entity, but each additional dimension makes distance computation more expensive. High dimensionality also weakens many coarse geometric filters because nearest and farthest distances become less distinguishable~\cite{beyer1999nearest,kouiroukidis2011effects,gao2023high,zhao2023towards}. Second, the maintained result is dynamic. Recomputing the full kNN join after every insertion or deletion is prohibitively expensive, so the system must accurately locate the rows that may change and repair only those rows. Third, efficient kNN join processing usually relies on indexes, but dual-dynamic maintenance requires more than a static or one-sided index. The index structures must accelerate search, support updates, and remain synchronized with the materialized join table under repeated changes~\cite{bohm2001cost,bohm2004k,xia2004gorder,yu2007efficient,yang2014continuous,ukey2023efficient}.

There are two broad paradigms for handling dynamic nearest-neighbor joins: approximate maintenance and exact maintenance. Approximate nearest-neighbor techniques are highly valuable for large-scale retrieval and serving workloads~\cite{bawa2005lsh,andoni2008near,jegou2010product,muja2014scalable,li2019approximate,gao2023high,zhao2023towards}. However, approximation changes the maintenance contract. In a fully dynamic join, an update may require both kNN computation and affected-query localization. If each approximate stage has a small probability of missing a true neighbor or an affected query, then even one query-side repair followed by one reference-side localization already creates multiple opportunities for the materialized table to deviate from the exact result; under a simple independent-error view, preserving correctness through two such stages has probability at most $(1-\epsilon)^2$, and the risk compounds across long update streams. This is especially problematic in high-stakes settings such as clinical decision support or financial monitoring, where a small missed neighborhood relation can trigger a much larger downstream error. Therefore, this paper focuses on exact dual-dynamic kNN join: after every update, the maintained table must match the result of recomputing the kNN join under the same distance metric and tie-breaking rule.

Our solution starts from a maintenance view of the problem. Fully dynamic kNN join can be understood as two coordinated maintenance paths over a materialized neighborhood view: one computes or repairs rows through kNN search after updates to $U$, whereas the other first identifies affected queries and then repairs only those rows after updates to $I$. To coordinate these paths, we propose a bidirectional locate-and-repair framework. It treats the join table as the primary maintained view and organizes each update around the search primitive needed to keep that view correct.

The framework is instantiated by \dualtree, a dual-index architecture for exact high-dimensional maintenance. Unlike one-sided dynamic kNN join settings that can rely on a single-side index, \dualtree maintains a \deltatree on the reference set $I$ for kNN search and row repair, and a dynamically maintained \hdrtree on the query set $U$ for RkNN search and affected-query localization. The two indexes are synchronized with the join table, so each update follows the right repair path. We also add leaf-level low-dimensional pruning and derive a cost-aware dimension-selection model.

In summary, this paper makes the following contributions:

\noindent(1) \emph{A dual-dynamic kNN join formulation.}
We study exact kNN join maintenance when both the query set and the reference set are mutable. The formulation emphasizes a materialized neighborhood table that must remain correct after insertions and deletions on both sides.

\noindent(2) \emph{A bidirectional locate-and-repair framework.}
We organize fully dynamic maintenance as two coordinated paths: kNN-based row computation and repair after updates to $U$, and affected-query localization followed by localized repair after updates to $I$.

\noindent(3) \emph{A dual-index instantiation.}
We propose \dualtree, which combines \deltatree-based kNN search over $I$ with dynamically maintained \hdrtree-based RkNN search over $U$. This design covers both search directions required by dual-dynamic maintenance and keeps the indexes synchronized with the join table.

\noindent(4) \emph{Fine-grained pruning and cost-aware dimension selection.}
We introduce a point-wise low-dimensional pruning stage at leaf nodes and derive a cost-aware model that selects the pruning dimensionality by balancing pruning power against projection cost.

\noindent(5) \emph{Comprehensive evaluation.}
We evaluate the proposed methods on eight real high-dimensional datasets with dimensionalities from 128 to 4096. The results show that \dualtree consistently outperforms strong one-sided baselines, while \dualtreeopt achieves an average speedup of 1.88$\times$ over the strongest one-sided baseline across seven additional datasets and up to 2.65$\times$ on Trevi.
