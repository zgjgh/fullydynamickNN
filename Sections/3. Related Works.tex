\section{Related Work}\label{sec:related-works}

\noindent\textbf{High-dimensional search.}
Exact and approximate kNN search have both been studied extensively. Exact methods include high-dimensional indexes and partitioning schemes designed to reduce unnecessary distance evaluations~\cite{yu2001indexing,cui2003contorting,cui2005indexing,garcia2010k,wang2013pl,xiao2016parallel,pan2020new,muhr2022hybrid}. Approximate methods, including locality-sensitive hashing, product-quantization, and recent graph-based ANN systems, trade accuracy for speed and scalability~\cite{bawa2005lsh,jegou2010product,muja2014scalable,wang2019new,li2019approximate,song2020brepartition,gao2023high,zhao2023towards,chen2023finger}. This trade-off is useful for retrieval workloads, but it changes the contract of a dynamic join maintenance algorithm. If an approximate method misses a point whose update changes a query's true kNN list, the materialized join table becomes incorrect. Therefore, approximate indexes are complementary serving components rather than direct substitutes for the exact maintenance problem studied here.

Some exact high-dimensional methods, such as iDistance~\cite{jagadish2005idistance}, rely on one-dimensional mappings, while others such as PL-Tree~\cite{wang2013pl} or exact filtering strategies~\cite{pan2020new} are mainly designed for standalone kNN retrieval. Our setting additionally requires reduced-space hierarchical pruning, exact verification, and mutable structure. This is why \deltatree~\cite{cui2003contorting,cui2005indexing} and \hdrtree~\cite{yang2014continuous} are used as the foundations of \dualtree, which maintains a join result under updates on both input sets.

\noindent\textbf{kNN and dynamic kNN joins.}
kNN join was introduced for computing kNN relationships between two datasets~\cite{bohm2003supporting,bohm2004k}. Representative static methods include MuX~\cite{bohm2001cost,bohm2004k}, Gorder~\cite{xia2004gorder}, and iJoin~\cite{yu2007efficient}. These methods improve over brute force through indexing, ordering, blocking, or dimensionality reduction, but they are not designed to maintain results under continuous updates. Distributed and stream-oriented variants further improve scalability or support stream processing~\cite{lu2012efficient,zhang2012efficient,zhao2017k,shahvarani2021distributed,bohm2006efficiently}, but they do not address exact bidirectional maintenance of a materialized high-dimensional kNN join.

Dynamic kNN join methods address update processing but remain largely one-sided. \hdrtree~\cite{yang2014continuous} and its successors~\cite{ukey2022efficient,ukey2023efficient,ukey2023knn} focus on continuous kNN join maintenance against a dynamic reference set using an index over the query side. A recent survey~\cite{ukey2023survey} similarly shows that dynamic kNN join has received far less attention than static kNN join. Existing approaches accelerate either forward kNN search or reverse localization, but not both under interleaved updates to $U$ and $I$. This limitation is structural rather than only implementational: a query update mainly needs a forward kNN computation, whereas a reference update first needs to identify affected query rows before their answers can be repaired. \dualtree treats the kNN join as a materialized view over two mutable inputs, so updates to $U$ and updates to $I$ follow different repair paths and are supported by dedicated index structures whose pruning values are maintained together.
